## What Went Well

### 1. Review caught the defects that make a desktop app feel unfinished

The first implementation was not accepted as done. The review then changed the code:

- 6-5 sent users to the marketing page after sign-in, registration, password update, and account deletion. Thirteen redirects were corrected to `/camera`.
- 6-10's image and data panes were unequal because flex padding was on the wrong element. A review also found the rail had no hover feedback.
- 6-11 left every destination inactive on `/appraisal`. The collapse control and the reclaimed pane width were corrected, and a Playwright test now performs the navigation check the task had claimed.
- 6-12 could leak a guest migration across accounts and could retry a permanent 422 forever.
- 6-13 could create two valuation rows for one key. The fix reserves the key before the AI call.
- 6-8 incremented the rate-limit bucket before an idempotent replay, so a legitimate retry could be rejected.

That is the Epic 5.5 review mandate working on the stories that used it.

### 2. Named debt from earlier retros got a story and closed

- Sidebar collapse was an Epic 3 complaint. 6-11 shipped it under the workstation rail.
- Offline migration retry was an Epic 4 complaint. 6-12 shipped an app-level queue. It deliberately did not add Background Sync to the service worker. 6-4 had reserved that decision, and 6-12 kept it.
- Idempotency was an Epic 5.5 action. 6-13 shipped the contract. Expired-row cleanup stays an operational follow-up, and the story says so.

### 3. 6-14 held its boundary and moved the only measurement we have

5.5-10 scored `gpt-4o-mini` and `gpt-4o` at 0/5, including HIGH-confidence Rolex and Herman Miller labels. 6-14 added a required `visible_observations` field, coerced ungrounded `HIGH` in the Pydantic model, and stopped generic keywords from collapsing to `"item"`. The same five photos were run once on `gpt-4o-mini`. None returned a famous unrelated product at `HIGH`. The model was not changed. Retrieval, readiness, and `SELL_NOW` were not edited.

The landing page (6-5) was also corrected to say estimates come from active market data, not guaranteed sale prices. That is the honesty rule, applied to marketing copy before Epic 8.

## What Did Not Go Well

### 1. Done is a status, not a commit

Epic 6 and Epic 8 edits are still mixed in the working tree. 6-12 and 6-14 both document files that contain hunks from more than one story. There is no git history that shows these fourteen stories as separate changes. A release cannot be cut from this tree without dragging unpublished evidence-integrity work with it.

### 2. The planned order was not the executed order

The Epic 6 plan put 6-13 and 6-14 in the first phase. Grounding finished last. The Epic 5.5 retro said to front-load visual grounding and called that story 6-13. Idempotency took the number 6-13. The grounding work exists. The sequencing commitment does not.

### 3. The review gate still has a hole

6-6 is `done` and the story file has no `## Code Review` section. That section was a high-priority action from the Epic 5.5 retro.

6-14's review was performed by the same model that finished the story. The review still found a real defect: blank and punctuation-only keywords were stored as searches. 6-10 and 6-11 were reviewed by a different model and also found high-severity defects. The project standard is the second one. 6-14 did not meet it.

### 4. Backend CI is still missing

`.github/workflows/ci.yml` runs frontend lint, typecheck, and tests. It does not run pytest. Epic 6 did not add that gate. Story 7-9 still describes it. Two local virtualenvs can both run the backend suite. A green local run is the only backend check.

### 5. "Overhaul" is a five-photo bar

6-14's pass bar was: the three hallucination photos must not come back `HIGH` on an unrelated famous product. That bar was met. It is not a general proof.

- The JBL photo produced the brand and left the model unknown. "Clip 4" is not printed on the grille. The completion notes originally called this a correct name. The review corrected that label.
- The controller photo shows a PlayStation logo. The model left brand and model unknown. That is the abstention the story asked for, and it is an under-call.
- A wrong brand at `MEDIUM` can still reach `SELL_NOW`. The story left that hole for Epic 8 on purpose.
- The check needs the local photo folder and a funded OpenAI account. The first attempt failed because the account had no credits.

6-10 also deferred a dedicated desktop capture layout and treated the existing file upload as enough. 6-4's background-sync idea was closed by choosing an app-level queue, which is a recorded decision, not a forgotten task.

### 6. Acceptance criteria did not keep the first draft honest

6-5 named a static-export path Expo does not emit. 6-11 recorded a browser check that had not been run. Review, not the written AC, was the control that corrected both. That is useful, and it means a story marked done before review is not done.

## Next Work

Two epics are defined. They are not equal.

**Epic 7, Accessibility & Polish**, is 14 backlog stories: contrast, touch targets, focus, alt text, semantics, live regions, bundle size, performance targets, CI/CD, reduced motion, cross-browser testing, monitoring, the OAuth cancel/expired paths, and the `SwissPressable` accessibility-state overwrite (7-14). Those acceptance criteria stay valid. They make the current report easier to perceive. They do not make the number honest.

**Epic 8, Evidence Integrity**, says it does not wait on Epic 6 or Epic 7. Story 8.1 is the first production change: stop presenting asking-price medians as a value, remove the broaden fallback, and stop `SELL_NOW`. 6-14 was written so it would not do that work.

**Sequence decided in this retro:** 8.1 comes before Epic 7 polish. Backend CI is preparation for that backend work, not a reason to open Epic 7. Epic 7 story creation waits until 8.1 is done.

### Significant discovery

Epic 7's story text assumes the product is ready to polish. Epic 6 showed the shell can be built while the evidence layer still overstates what the user is looking at, and while the shell itself is uncommitted. Starting 7-1 in that state polishes the wrong surface.

Epic 7 does not need its acceptance criteria rewritten. It needs a sequence lock. Epic 8's plan already contains the right sequence. This retro confirms it.
